## R2 DexGrasp 官方 raw 兜底仅覆盖 6 个物体

| 项 | 说明 |
|---|---|
| 影响题目 | `ss_dexgrasp_001`（banana，有兜底）、`ss_dexgrasp_002`（apple，**无兜底**）、`ss_dexgrasp_003`（mug，有兜底）、`ss_dexgrasp_004`（bottle，有兜底）、`ss_dexgrasp_005`（scissors，**无兜底**） |
| 现象 | HF 仓库（如 DexGraspNet2.0）grasp 数据仅在大体积 tar.gz 中；官方 GitHub raw 单物体 `.npy` 兜底只收录 6 个物体：banana / mug / bottle / camera / plant / plate |
| 根因 | 官方 `data/dataset/` 仅 5 个文件条目（实测确认），apple / scissors 等物体官方仓库就没有独立单物体文件 |
| 现状 | 覆盖物体走 raw 兜底返回真实 `.npy`（已验证网络可达）；未覆盖物体走 metadata JSON（format `json` 在问题集预期内） |
| 判定建议 | 命中真实 `.npy` 的（banana/mug/bottle）判 PASS；未覆盖的（apple/scissors）判 **PASS_WITH_FALLBACK**，与 R1 同口径 |
| 升级路径 | 若要求 apple/scissors 返回真数据，需换用其他源（GraspNet 对应物体类）或扩充 `_DEXGRASP_DATASET_FILES`（需官方文件存在） |

## R4 目标解析对 fallback_sources 的选源依赖 LLM 随机性

| 项 | 说明 |
|---|---|
| 影响题目 | `ms_008`（P1，多源 end_to_end，Franka Panda URDF）；机制上波及所有依赖 LLM 推断 fallback_sources 的题目 |
| 现象 | 前端真实流程 3 轮检索-校验迭代全部未命中 → **FAIL/P2_RETRIEVE**（run_id=20260818-200031-4a35c1ee）；同一时刻同输入脚本直跑（探针）却命中 github 兜底 → **PWF**（package-20260818-192816，19 文件）。两次唯一变量是 LLM 采样输出 |
| 根因 | `node_parse_goal` 的 `fallback_sources` 完全由 LLM 从自由文本推断，prompt 仅提供枚举清单、无 robot_urdf 类的确定性选源规则（对比 sensor_data 已硬编码 `["zenodo","github"]`）；本次把源选为 allegro/robotiq/kinova，三源白名单均不含 Franka Panda，检索"有源但未收录"全 miss，迭代回退救不回 |
| 现状 | 结果已如实入库（ms_008 FAIL，executor=F+A）；前端不静默降级，符合合规要求；记录见 `records/ms_008/record.json` |
| 判定建议 | 此类由 LLM 选源随机性导致的失败按 **P2_RETRIEVE** 记录，并保留探针对照作为旁证；不得以探针成功结果改写前端失败结果 |
| 升级路径 | ① 在 `_normalize_datareq` 增加确定性选源规则（与 sensor_data 同构）：已知厂商机器人（Franka/Kinova/UR5 等）的 `robot_urdf` 强制优先 `["franka","github"]` 类源，LLM 偏离时按规则覆盖；② 或把题设源作为约束注入 parsing prompt。已建议纳入 Day6 复盘改进清单 |
