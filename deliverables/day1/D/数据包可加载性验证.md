# 数据包可加载性验证

数据包生成后，不能只确认文件已落盘，还必须用真实工具把产出文件逐一加载起来，验证其"能打开、能解析、能运行"，避免出现"文件在但其实是坏数据"的情况。验证按数据类型分三类进行：

## URDF（机器人模型）

使用 `yourdfpy` 库加载，并开启 `load_meshes=True` 参数。这一步不仅验证 URDF 文件本身能否被正确解析，还会顺带加载 URDF 中引用的所有 mesh 网格文件，确保机器人模型的几何描述完整可用。加载失败即判定为格式问题或运行时问题。

## Mesh（物体网格）

使用 `trimesh` 库加载 obj/stl 等网格文件，并检查加载后的面数（faces）是否大于 0。面数大于 0 说明文件不是空文件、也不是损坏的网格，可以作为有效的 3D 模型使用。

## MJCF（MuJoCo 场景配置）

使用 `mujoco` 库加载 MJCF/XML 场景文件，并调用 `mujoco.mj_step` 让仿真引擎**实际执行一步仿真**。这一步验证场景不仅能被解析，还能被 MuJoCo 引擎正常初始化并完成物理步进，是"能不能跑起来"的最直接检验。

## 判定标准

三类文件若全部通过各自验证，则数据包满足可加载性要求；若某类文件加载失败或运行报错，则该题判定为 FAIL，并标注失败分类码：

- **P4_FORMAT**：格式不兼容（如 xacro 变体、glb 格式、python 场景脚本等，工具无法解析）；
- **P5_RUNTIME**：运行时验证失败（如 MuJoCo 加载报错、mesh 缺面/空面等，能解析但跑不起来）。
