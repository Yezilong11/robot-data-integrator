### 6.2 arxiv PDF 打开失败（P4_FORMAT，4 轮复现）——具体根因与修改方法

#### 具体根因（已定位到代码）

**问题不在 fetch 层，而在下游解析层没配套改。** 整条链路：

```
ArxivAdapter.fetch
  ├─ HEAD 预检 Content-Length > arxiv_max_fetch_bytes(2MB) → 返回 metadata JSON（format=json，不下载）
  ├─ 下载后 _is_valid_pdf 校验（fitz 实际打开验证魔数+结构+页数）
  │    └─ 无效 → 重试一次 → 仍无效 → _metadata_fallback 返回 metadata JSON（format=json）
  └─ 有效 → RawData(format="pdf")
        ↓
parse_convert → SkillRegistry.process_retrieval_result
        ↓ skill.process(raw.data, fmt=raw.format, ...)
PaperSkill.process(data, **kwargs)
        ↓ 忽略 fmt 参数
fitz.open(stream=data, filetype="pdf")  ← JSON 字节当 PDF 打开 → "Failed to open stream"
```

关键代码点：

1. **fetch 层已正确降级**（[arxiv.py](file:///d:/tiaozhanbei/robot-data-integrator/src/rdi/adapters/arxiv.py#L51-L87)）：`_is_valid_pdf` 用 PyMuPDF 实际打开校验（仅查 `%PDF` 魔数不够——国内网络会拿到"魔数正确但结构损坏"的字节），无效时返回 `format=json` 的 metadata（含 url/size/title/abstract + `RawReference`）。
2. **解析层未适配 format=json**（[paper_parse.py](file:///d:/tiaozhanbei/robot-data-integrator/src/rdi/skills/paper_parse.py#L23-L56)）：`PaperSkill.process(self, data, **kwargs)` **忽略 `fmt` 参数**，无论 pdf 还是 json，一律 `fitz.open(stream, filetype="pdf")`。而 [registry.py](file:///d:/tiaozhanbei/robot-data-integrator/src/rdi/skills/registry.py#L178) 已传入 `fmt=raw.format`，但 PaperSkill 不消费。
3. **结果**：fetch 降级成 JSON（生产者已改）→ PaperSkill 仍把 JSON 字节当 PDF 打开（消费者没改）→ 报 `无法打开 PDF: Failed to open stream` → manifest `missing_items` 原样记录 → 4 轮复现。

> 一句话：**降级契约（format=json）与解析契约（pdf）不匹配**。只改了生产者，没改消费者。

#### 具体修改方法（供 A 评审，未改动代码）

**方案 A（推荐，改动最小）**：`PaperSkill.process` 增加 `fmt` 分支——当 `fmt == "json"` 时，把 metadata 字节直接装配为成功结果（`canonical_format="json"`），不再走 `fitz.open`：

```python
def process(self, data: bytes, fmt: str | None = None, **kwargs: Any) -> StandardResult:
    if fmt == "json":
        try:
            meta = json.loads(data.decode("utf-8"))
        except Exception as exc:
            return StandardResult(success=False, canonical_format="json",
                                  errors=[f"metadata JSON 解析失败: {exc}"])
        return StandardResult(
            success=True,
            canonical_format="json",
            data=meta,
            completeness_pct=60.0,   # 显式降级：仅元数据，无 PDF 全文
            confidence_score=0.6,
            warnings=["PDF 不可用，返回元数据（fetch 降级）"],
        )
    # ... 原有 PDF 打开逻辑 ...
```

注意 `registry.py` 的 `_format_mismatch_reason` 会先校验格式：需确认 `_REQ_EXPECTED_FORMATS[PAPER]` 包含 `"json"`（或不校验），否则 json 会在装配前被记 MissingItem（类型错配）。

**方案 B（更完整）**：fetch 降级时不仅返回 metadata，还将 `RawReference`（含 pdf_url）透传；PaperSkill 对 `fmt=json` 分支把 `reference` 写入 `ParsedItem` 的 alternatives / provenance，前端「数据包审查」可见手动下载链接。

**方案 C（网络层，可选）**：调整 `ARXIV_MAX_FETCH_BYTES`（默认 2MB，若网络允许可调大到 50~100MB 下载全量 PDF），或换镜像下载；属于参数/网络层，与 A/B 不冲突。

**落地顺序建议**：A 先裁定判定口径（`fmt=json` 降级按 PASS_WITH_FALLBACK 还是仍记 FAIL/P4_FORMAT）→ 实施方案 A/B → 重跑 ss_arxiv_001 验证。
