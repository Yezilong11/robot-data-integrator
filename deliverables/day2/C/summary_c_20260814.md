## 六、问题解决方法（待实施）

> 参数默认值来源：`src/rdi/config/settings.py`（feat/arch-langgraph 分支）。以下为建议方案，是否落地由 A 评审裁定后执行。

### 6.1 arxiv 检索超时（P2_RETRIEVE / error_type=timeout）

- **根因**：`per_req_timeout=60.0` 为单个需求检索的总超时预算，arxiv search 在本分支（含多关键词逐个尝试 + 国内网络）超过 60s 未返回，被 `asyncio.timeout` 显式拦截。
- **解决方法**（按优先级）：
  1. 复核并调大 `PER_REQ_TIMEOUT`（建议 120~180s），给检索留足余量；
  2. 探活确认 arxiv 在当前网络下 search 的真实时延（旧分支探活 1.2s，本分支待实测）；若 arxiv.org 持续慢，考虑 API 镜像/代理；
  3. 若需下载全量 PDF：调大 `ARXIV_MAX_FETCH_BYTES`（默认 2MB → 如 100MB，`ARXIV_MAX_FETCH_BYTES=100000000`）；
  4. 判定口径确认：显式超时记 P2_RETRIEVE 正确（非静默失败），不作为执行人问题。

### 6.2 LLM grasp 歧义误判（P1_PARSE，github/huggingface 均中招）

- **根因**：目标含「抓取/grasp」时 parse_goal 倾向判为 GRASP，未结合「仓库/数据集/dataset」上下文。
- **解决方法**（可组合实施）：
  1. **题面层（问题集）**：调整 target 措辞消除歧义——
     - `ss_github_001` → 「检索 Franka 抓取相关的**开源代码仓库**」
     - `ss_huggingface_001` → 「检索 robot grasp **数据集（dataset）**」
  2. **prompt 层（parse_goal）**：`src/rdi/intelligence/prompts/goal_parsing.py` 增加消歧规则与 hint 词表：含「开源仓库/代码/code」→ CODE；含「数据集/dataset」→ DATASET；「grasp」单独出现时按上下文（dataset/repo 等限定词）判定而非直接 GRASP。
  3. **测试层**：parse_goal 单测补充「抓取开源仓库→CODE」「grasp dataset→DATASET」「抓取 banana→GRASP」三组歧义回归用例。
  4. **判定层**：同题多次执行结果漂移时，以题面意图为准（A 定「结果以 X 为准」口径）。

### 6.3 graspnet 仅返回元数据 JSON、无真实 npz（not_found）

- **根因**：目标 grasp 文件超过 `max_fetch_bytes=50MB` 下载阈值，HEAD 预检返回 metadata JSON（大文件参考路径）——属设计行为（避免下载超时），非 bug。
- **解决方法**（按优先级）：
  1. **本地数据集挂载（推荐）**：配置 `LOCAL_DATASETS` 挂载 graspnet 目录，fetch 优先本地直读真实 npz（`source=local`），不发网络请求——
     `LOCAL_DATASETS={"graspnet":"D:/datasets/graspnet"}`
  2. 调大 `MAX_FETCH_BYTES` 允许下载真实大文件（注意网络/磁盘成本）；
  3. **判定口径统一**（需 A 拍板）：元数据 JSON + manifest `missing_items` 显式记录 = **PASS_WITH_FALLBACK**（显式降级，包可用但无真实文件）；当前按 files=0 记 FAIL。两者择一并写入判定口径纪要，避免口径漂移。
